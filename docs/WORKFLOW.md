# 工作流：为什么这么分工，尺度怎么换算

## 1. 两层流水线

```
        ┌──────────── QGIS（只画地图） ────────────┐
工程 .qgz → 图层样式（临时按出图尺度放大） → render_map.py → map_xxx.png（素图）
        │                                       → map_xxx.json（extent / mpp）
        └───────────────────────────────────────┘
                          ↓
        ┌──────────── Pillow（只排版） ────────────┐
素图 + 文案 → compose_xxx.py → 4960×3507 展板 → 成品/NNxxx.png
        └───────────────────────────────────────┘
```

**分工原则**：地图里只留「地理事实」（面、线、点、标注），一切**说明性**的东西（标题、图号、图例、KPI、正文、比例尺数字、数据来源）都归排版层。

这样带来三件事：

- **样式不会被排版污染**。渲染时改的样式只活在内存；排版层永远不动 QGIS 工程。成套出图时这是最大的省心点。
- **可复跑**。改一个数字 → 重跑 `compose_xxx.py`（几秒）；改图层颜色 → 重跑 `render_map.py`（几秒）+ 排版。
- **可批量**。12 张图的标题/图例/脚注是 12 个函数，共用一个 `board_lib`；整册视觉一致性由库保证，不靠手调。

代价：素图是位图，放大看会糊。所以 **素图分辨率必须大于等于排版里的贴图尺寸**，见下节。

## 2. 尺度换算（最容易翻车的地方）

### 2.1 三个尺度，别混

| 环节 | 尺度 | 说明 |
|---|---|---|
| 屏幕看 | 96 dpi | QGIS 画布上 1 mm 线你觉得刚好 |
| 素图 | 2900×2300 @300 dpi | 渲染时 QGIS 认为 1 mm = 11.81 px |
| 展板 | 4960×3507 @300 dpi | 素图贴进 2900×2300 的版心 |

`dpi` 只影响 **mm ↔ px** 的换算，不影响像素尺寸。所以「线上看着粗、出图变细」的根因不是 dpi，而是**同一根 0.26 mm 的线，在 2000 px 宽的图里只占 1 px**。

### 2.2 出图前把样式乘 k

经验值（素图宽 ≈ 版心宽时）：

| 素图宽 | 贴进版心后的缩放 | 建议 k |
|---|---|---|
| 2900 px | 1.0×（1:1） | 2.4 – 3.0 |
| 5800 px | 0.5× | 4.0 – 5.0 |
| 1450 px | 2.0× | 1.2 – 1.5 |

用法（在 spec 里）：

```json
"scale": {"k": 2.6, "layers": ["廊道", "节点", "水系"]}
```

它在 `render_map.py` 里调用 `scale_styles.scale_layers(k, layers)`，把线宽、符号大小、描边、白晕、标注字号与 buffer 一起乘 k。**跑完一定要看素图**：文字可能撞在一起，标注重叠就去 spec 里减图层或改标达式。

> 为什么不在排版层放大？位图放大必糊。线宽必须在渲染时就足量。

### 2.3 extent / CRS：必须同一套

`render_map.py` 的规则：

- 给了 `extent` → 按 `crs`（缺省 = 工程 CRS）解释这四个数；
- 没给 → 取 `fit.layers` 的并集（图层 CRS 不同会先转换），按 `pad` 外扩，再按画布纵横比裁齐（避免拉伸）。

踩过的坑：extent 用 EPSG:4547 的数值（`761224, 4333544…`），但地图 CRS 用了工程 CRS（3857）→ 视口跑到非洲，出来纯白。**extent 的数值和 CRS 必须是一套**。

### 2.4 比例尺

排版里的比例尺用素图元数据的 `mpp`（每像素米数）：

```python
mpp = meta['mpp']            # = extent.width / width_px
scalebar(d, mpp, x, y, 1000)  # 1 km 那条黑带的长度 = 1000 / mpp 像素
```

注意素图贴进版心会被缩放，所以真实比例是 `mpp / 缩放比`。多数时候不需要报「1:xxxx」，报「0 — 500 — 1000 米」就够了（我们的板式就是这样）。

`bar_m` 不用给 —— `scalebar` 会按 `mpp` 自动挑一档，让画出来的黑带落在 220–640 px。手动指定时记住：**一个 1 km 的带子在小比例尺素图里可能只有 50 px，三个标签会叠在一起**，这时要么换档，要么只留首尾两个标签。

## 3. 版式网格

A3 4960×3507 的固定网格（`board_lib` 里已经写死，改之前想清楚）：

```
x=0 ──────────────────────────────────────────────── 4960
  160  药丸标签(140)                                   3060 3200       4720
   │   标题基线 300，居中                                │    │ 右栏文字宽 1520
   │   ┌──────────────────────┐                        │    ┌──────────┐
  600│   │                      │                        │ 600│ 小标题   │
   │   │      地图区           │                        │    │ 正文     │
 2900│   │  2900 × 2300         │                        │    │ KPI 2520 │
   │   └──────────────────────┘                        │    └──────────┘
 2940  图例（每行 4 条，条宽 720）───────────────────────
 3060  图例第二行
 3110  灰色口径注 38px
```

- 地图区 `(160,600)–(3060,2900)`：贴图函数 `paste_fit` 会等比缩放到框内居中，所以素图纵横比不必等于 1.2609，只会有留白。
- 右栏 `x=3200`：`section()` 每次吃掉 `fs+30` 的高度，`para()` 每行 `lh`；**排完打印一次 `y`**，超过 2900 就会和图例打架（`compose_green.py` 里就有 `print('ends at y =', ...)`）。
- 三图板（如服务半径三张并排）：每张宽 1480，间隔 40，左起 160。

## 4. 一套图的组织方式

```
项目/
  map_土地现状.png  map_土地现状.json      ← 素图 + 元数据，成对
  map_绿地系统.png  map_绿地系统.json
  compose_all.py                            ← 一板一个函数 b01…b13
  board_lib.py
  成品/
    01区位分析图.png  …  13发展定位图.png    ← 文件名即排序
```

`compose_all.py` 的写法：每个 `bNN()` 只管自己的文案与素图，公共样式全在 `board_lib`。想改整册的字号，改库，13 张一起变。

## 5. 交付前检查

- [ ] **尺寸**：每张 4960×3507（A3 300dpi）。A1 展板需要 9933×7016，素图也得跟着重渲，别把 A3 的拉大。
- [ ] **色彩**：sRGB 交给打印店；要 CMYK 先问店家要不要，自己转容易偏色（红会发暗）。
- [ ] **字体**：本 kit 全程位图，不存在「字体没嵌入」问题；这也是这套流水线比 PDF 省心的地方。
- [ ] **出血**：图册内页不需要出血；做展板时四周留 3–5 mm 白边（我们的版式本来就有边距）。
- [ ] **打包**：`成品/` + 一份 `数据来源与口径.txt`（数据年份、坐标系、面积统计口径），答辩时被追问能立刻答。
